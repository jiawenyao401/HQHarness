# HQHarness desktop release runbook

Use the [HQHarness release guide](hqharness-release.md) for the current configuration, signing secrets, workflow modes, publication destinations and installed-app acceptance requirements. The upstream DSH Desktop distribution services and signing identity are not HQHarness release inputs. No HQHarness official download site or signed public release is assumed by this repository.

## Native build gates

The `HQHarness desktop installers` workflow builds macOS Apple Silicon, macOS Intel and Windows x64 on their matching native runners. Every target runs `npm ci` with postinstall, builds once, tests the prepared runtime, runs typecheck and packages with `scripts/verify-target.mjs`. PR and development runs do not need production signing secrets. They use a separate `HQHarness Dev` identity and `hqharness-dev` profile.

Brand assets are generated by `npm run brand:prepare` before frontend installation and compilation. `build/brand-mark.svg` and `brand.config.json` are authoritative; `.build/brand/` is generated and excluded from Git. Validate the actual package input rather than a stale icon copied into `build/`.

PPT packages are generated under `.build/ppt-runtime/packages/` and overlaid into the Electron package. The `afterPack` gate in `scripts/after-pack.cjs` loads `dsh-ppt` and `dsh-ppt-composer` through `app.asar` on the packaged Electron runtime, including native imports and template previews. It fails when an OS-loaded Mach-O, ELF or PE file is packed inside ASAR rather than unpacked. The Office gate executes packaged Python and skills, generates/reopens DOCX/PPTX/XLSX, validates OPC slash paths and converts all three using packaged LibreOffice. See [Office runtime](office-runtime.md).

JavaScript dependencies load from `app.asar`. Only native binaries, libraries, helpers and other OS-executed resources are unpacked. Neither platform ships a standalone second Node runtime: Windows uses the packaged Electron executable in Node mode, and macOS uses its Helper. Any Electron or native-loader upgrade must pass packaged Harness and installed Windows acceptance again.

## Signing and installation gates

macOS signing imports a self-owned Developer ID certificate into a temporary keychain, notarizes and staples app/DMG, then checks both architectures with `codesign`, `spctl` and `stapler validate`. Temporary signing files are cleaned on success or failure. Unsigned development artifacts are not evidence of a signed production build.

Windows packaging and signing are separate jobs. A GitHub-hosted native runner builds unsigned NSIS. A dedicated self-hosted runner with the `hqharness-signing` label downloads and verifies the artifact, scans all PE files by content, preserves vendor signatures, signs unsigned application binaries, signs the NSIS extraction helper/uninstaller during repackaging, then signs the final installer and regenerates blockmap and metadata. Missing input, malformed PE or any signing failure stops the release. The signing PIN is never logged and is kept in a temporary mode-600 file.

The final signed installer must pass the Windows installed-app smoke: expected self-owned publisher, all PE signatures, Harness boot, packaged Office, same-path upgrade and Profile preservation. The NSIS staged-directory installer promotes the new directory only after extraction succeeds and restores the old directory on failure; the smoke also tests a locked executable. A different selected installation directory is an independent installation. Keep the directory-selection and rollback behavior intact when changing the NSIS adapter.

## Publication and retention

GitHub Release and Pre-release jobs wait for every required native, signing and installed-app gate, verify release assets, and publish only into the explicitly configured self-owned `releaseRepository` matching `GITHUB_REPOSITORY`. Protected `hqharness-release` and `hqharness-signing` environments and restricted tag/workflow changes should be configured before the first release. Do not reuse a public release tag.

Development artifacts are retained 3 days, signed results 7 days and unsigned Windows signing handoffs 1 day. GitHub Release is the durable distribution copy. Run `resign` or `smoke` while source artifacts still exist. Compressed installers upload with `compression-level: 0`.

The explicit archive-backup workflow downloads and validates existing self-owned GitHub assets and saves a 7-day backup artifact with SHA256SUMS. It does not update a remote rollback catalog. HQHarness has no automatic upstream mirror, business notification or rollout integration. With an update service configured, validate both metadata architectures, checksums, publisher verification and a real installed-app update before enabling distribution.
